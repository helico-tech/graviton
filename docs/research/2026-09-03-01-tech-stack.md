# Graviton technology stack evaluation

Date: 2026-09-03. Machine: Linux x86_64, 8 CPUs, 15 GB RAM, no real GPU
(virtio; Mesa lavapipe/llvmpipe present). All versions below were read from
the npm registry, crates.io, PyPI, and GitHub on this date, not from memory.
Every measurement was taken on this machine; probe sources live in
`scratchpad/research/stack-probe/`.

## 1. Summary

**Recommendation: TypeScript everywhere, Canvas 2D renderer, no engine.**
Vite 8.2.2 for dev and build, Vitest 5.0.0 for unit and golden tests,
Playwright 1.62.1 for browser smoke tests and real-browser screenshots,
`@napi-rs/canvas` 1.0.8 so the *same* renderer code produces PNGs in Node
without a browser, oxlint 1.81.0 as the guard-rail enforcer, pnpm 11.25.0 as
package manager, Node 24 LTS as runtime. Zero runtime dependencies in the
shipped game apart from two self-hosted fonts.

Runner-up: a Rust simulation core compiled to WASM behind the same TypeScript
renderer. It wins on determinism (verified bit-identical across four JS
engines and native) and loses on two-language maintenance cost. The
recommended layout keeps the simulation behind a narrow command-in,
state-and-hash-out boundary so that this remains a bounded later migration if
JavaScript planner performance ever falls short.

Three findings shaped the ranking:

1. **JavaScript `Math.sin` and friends are not stable even across V8
   versions.** Node 24 (V8 13.6) and Chrome 151 (V8 15.1) produce different
   bits for sin, cos, tan, atan2, exp, log, cbrt, asin, acos, expm1, log1p,
   sinh and atan over a 20 000-value sweep. Firefox 153 and Bun (JavaScriptCore)
   differ again. Only `sqrt`, `pow` and `hypot` agreed, and pow/hypot are not
   guaranteed to. Pure arithmetic (`+ - * /`) was bit-identical across all
   four engines, Rust native x86_64, and WASM in four engines (same FNV-1a
   hash `6960db772e303d7a`). So the simulation must own its transcendental
   functions, written in plain arithmetic, and a lint rule must keep `Math.*`
   out of it. With that guard-rail, TypeScript is as deterministic as WASM.
2. **Headless rendering without a browser is real and cheap.** A renderer
   written against a small `Ctx2D` interface ran unchanged on
   `@napi-rs/canvas` in Node (0.08 s wall, 88 MB RSS) and in headless Chromium
   via Playwright (0.93 s, 205 MB). The two PNGs are visually identical.
3. **Native Rust game libraries fail the headless requirement on this
   machine.** macroquad panics with `XOpenDisplay() failed` and there is no
   Xvfb. wgpu *does* render offscreen through lavapipe with no display
   (verified, 0.09 s), but it costs 72 crates and a 21 s cold dependency build
   before any game code, and its API changed enough between what I knew and
   30.0.1 that a first-attempt probe failed to compile three times.

GitHub Pages, tests, and long-term agent maintainability.

## 3. Candidates

### 3.1 TypeScript + Canvas 2D, Vite, Vitest (no engine)

Versions: typescript 7.0.2 (`latest`, published 2026-07-08), vite 8.2.2
(2026-08-20; Rolldown and Oxc built in, esbuild gone), vitest 5.0.0
(published today; 4.1.11 is the previous line and also supports Vite 8),
@playwright/test 1.62.1, @napi-rs/canvas 1.0.8, oxlint 1.81.0.

Measured on this machine with pnpm:

| Measurement | Result |
|---|---|
| node_modules for the full toolchain | 138 MB (oxlint 16, rolldown 19, TS native 27, napi canvas 33, playwright-core 14) |
| `pnpm install` with a fresh store dir | 3.8 s wall, 807 MB peak RSS |
| `tsc -p` (TypeScript 7 native) | 0.49 s, 134 MB |
| `vite build` | 0.62 s, 135 MB, 1.1 kB JS output for the probe |
| `vitest run` (one file) | 0.83 s, 135 MB |
| Node headless render to PNG via @napi-rs/canvas | 0.08 s, 88 MB |
| Playwright Chromium screenshot of the Vite dev page | 0.93 s, 205 MB, zero console errors |

Headless drive and screenshots. Two paths, both verified, sharing one
renderer:

- **Node, no browser.** `src/render` draws against a `Ctx2D` interface that is
  a subset of `CanvasRenderingContext2D`. A CLI (`pnpm render --level 07
  --tick 4200 --out shot.png`) loads the level, replays the command log to the
  tick headlessly, renders into an `@napi-rs/canvas` canvas and writes a PNG.
  Fonts are registered from the same woff2/ttf files the web build ships, so
  glyphs match. This is the path an agent uses in a loop: it is 10x faster
  than a browser and needs no display.
- **Real browser.** Playwright launches the cached Chromium
  (`~/.cache/ms-playwright/chromium-1234`, which is exactly what 1.62.1 wants,
  so no download), opens `/?level=07&tick=4200&paused=1`, optionally calls
  `page.evaluate(() => graviton.step(100))` through a `window.graviton`
  handle, and screenshots the canvas. Console errors are captured and fail
  the test.

Runtime footprint. Canvas 2D with a few hundred objects and a few thousand
trajectory points is trivial for the browser. Because nothing animates unless
simulated time moves, the loop can call `requestAnimationFrame` only while
running and redraw on input while paused, giving zero idle CPU. Expect a tab
of roughly 50 to 80 MB.

Determinism. Arithmetic is exact IEEE-754 double in every engine; there is no
FMA contraction, no extended precision, no fast-math in JavaScript. The only
hole is the transcendental library, which my probe showed changes between V8
13.6 and 15.1. Guard-rails in section 6 close it. WASM-level cross-platform
identity is then achievable in plain TypeScript, since the pure-arithmetic
hash matched Rust native and WASM bit for bit.

Dense text UI. The plot is a canvas; the status bar, selection panel and
timeline are HTML with CSS `font-variant-numeric: tabular-nums`, monospace
fonts, hairline borders. `setLineDash`, `ellipse`, 1 px strokes and clip
paths for banded sphere shading are native Canvas 2D calls. This is the
easiest candidate for the aesthetic spec by a wide margin.

Tests. Vitest for the sim (golden replay, ghost, warp, serialization,
substep), Vitest plus napi canvas for render snapshot tests, Playwright for
smoke tests and cross-engine parity. Vitest 5 requires Node 22.12+ and Vite
6.4+; both satisfied.

Maintainability. One language, one package, zero runtime dependencies,
APIs (Canvas 2D, DOM) that have been stable for fifteen years and that every
model knows cold. TypeScript 7's programmatic API is not stable until 7.1, so
`typescript-eslint` and `vite-plugin-checker` cannot run on it; oxlint does
not need it and its type-aware engine (`oxlint-tsgolint` 7.0.2001) is built
on the same Go compiler. Node 24 strips types natively, so `scripts/*.ts`
run with plain `node` (verified) and helper scripts stay in the project's
language with no build step.

### 3.2 TypeScript + WebGL/WebGPU via PixiJS 8 (or raw WebGL)

Versions: pixi.js 8.20.1 (2026-08-26). Bundlephobia: 902 kB minified, 258 kB
gzipped. Since 8.16 there is an experimental Canvas renderer.

Headless. WebGL2 works in headless Chrome here through SwiftShader
(verified: renderer string `WebKit WebGL`), so Playwright screenshots are
possible. There is no Node path: Pixi needs a GL or WebGPU context, and the
experimental canvas renderer is not documented to run on a Node canvas. Every
screenshot costs a browser launch and software rasterisation of a GPU
pipeline, which is the opposite of low CPU.

Fit. Pixi's strengths are sprites, batching and filters. The aesthetic wants
1 px lines with dash patterns, hairline rings, text with tabular numerals and
flat banded shading. Pixi Graphics has no native dash support, its text is
rasterised through a hidden canvas anyway, and raw WebGL would need a line
shader, a dash shader and a glyph atlas before drawing the first ellipse.
Bundle size and API churn (8.x releases every few weeks) raise maintenance
cost without buying anything the design needs. WebGPU is not required by any
part of the spec.

Determinism. Same as 3.1; the renderer does not touch state.

### 3.3 TypeScript + SVG/DOM renderer

Versions: @resvg/resvg-js 2.6.2 for Node-side rasterisation.

Headless. Good: the renderer can emit an SVG string, and `resvg-js`
rasterises it to PNG in Node without a browser; Playwright covers the real
browser. Text, dashes, ellipses and clip paths are all native SVG.

Runtime. The weak point. At warp the plot updates every frame, and a scene of
a few hundred elements with long `<path d>` trajectories means attribute
churn, style recalculation and garbage per frame. Nine orders of zoom with
`transform` on a group is fine, but redrawing thousands of path points via
DOM strings each frame costs several times the CPU of a canvas redraw. With
"low CPU" as priority one, this loses to canvas while being otherwise close.

Dense text UI: excellent. Maintainability: good. Tests: as 3.1.

### 3.4 Rust core to WASM (wasm-bindgen) + TypeScript renderer

Versions: rustc 1.95.0 with `wasm32-unknown-unknown` already installed,
wasm-bindgen 0.2.127, wasm-bindgen-cli 0.2.127 (must match exactly; not
installed, `cargo install` compiles it in a couple of minutes, or wasm-pack
0.15.0 downloads a matching binary), vite-plugin-wasm 3.6.0, libm 0.2.16,
serde 1.0.229, criterion 0.8.2, insta 1.48.0.

Measured:

| Measurement | Result |
|---|---|
| Minimal wasm-bindgen crate, cold release build for wasm32 | 5.6 s, 367 MB, 9 crates |
| Output `.wasm` (opt-level s, lto) | 41 kB |
| Plain `extern "C"` cdylib, no bindgen | 19 kB, runs in Node and browsers with the raw WebAssembly API |
| Cargo target dir after all Rust probes | 942 MB |

Determinism, verified. I hashed `f64::sin`, `libm::sin`, `atan2` and a pure
mul-add chain over 20 000 inputs:

| Build | std sin | libm sin | libm atan2 | mul-add chain |
|---|---|---|---|---|
| Rust native x86_64 (glibc libm) | `e488c7d7…` | `dea066c3…` | `1a27d232…` | `6960db77…` |
| WASM in Node 24 (V8) | `dea066c3…` | `dea066c3…` | `1a27d232…` | `6960db77…` |
| WASM in Bun (JavaScriptCore) | same | same | same | same |
| WASM in Chromium 151 | same | same | same | same |
| WASM in Firefox 153 | same | same | same | same |

Core WASM has no transcendental instructions, so `f64::sin` on wasm32 is the
pure-Rust `libm` port and is bit-identical in every engine. Native Rust's
`f64::sin` calls glibc and differs; using the `libm` crate explicitly makes
native and WASM agree. This is cross-platform bit-identity, the contract's
stretch goal, essentially for free (NaN payloads excepted; avoid NaN).

Costs. Two toolchains and two test runners for the sim (cargo test natively,
Vitest against the WASM build), a serialisation boundary for the renderer
(expose `Float64Array` views over WASM memory, or copy), wasm-bindgen CLI
version pinning, harder debugging in the browser, and an agent that must
maintain idiomatic code in two languages. The planner's interactive
re-integration would run 1.5x to 3x faster than V8 JIT code; for a few
hundred dynamic objects against a handful of attractors, V8 is already far
inside budget. Worth it only if profiling proves otherwise.

### 3.5 Pure Rust native (macroquad, wgpu, egui) with offscreen screenshots

Versions: macroquad 0.4.16, miniquad 0.4.11, wgpu 30.0.1, egui and eframe
0.36.1, egui_kittest (snapshot testing, prefers software rasterisers),
tiny-skia 0.12.0 (software 2D, no text), fontdue 0.9.4, image 0.25.10,
trunk 0.21.14 for a web build.

Measured:

| Measurement | Result |
|---|---|
| macroquad probe, cold release build | 6.8 s, 37 crates, 1.5 MB binary |
| macroquad run with no DISPLAY | panic: `XOpenDisplay() failed!`; no `xvfb-run` or `Xvfb` on the machine |
| wgpu 30 dependency tree, cold debug build | 21.3 s, 865 MB RSS, 72 crates |
| wgpu headless clear-and-readback to PNG, no display | works via lavapipe (`llvmpipe`, Vulkan, type Cpu), 0.09 s, 122 MB |

Headless. Only the wgpu route works without a display, and only because Mesa
lavapipe happens to be installed; on GitHub-hosted runners it also is, but
that is a system dependency outside the repo. egui_kittest gives snapshot
tests through the same software path.

GitHub Pages. Requires compiling the whole app to WASM with WebGPU or WebGL2
fallback through trunk; eframe web bundles are several MB, and the browser
build of a wgpu app is a second build target with its own bugs. Doable, not
"easy".

Dense text UI. egui is immediate-mode with its own font rasteriser; dense
monospace panels are possible but styling to the palette and tabular numerals
means fighting the widget theme. macroquad text is basic. Neither has 1 px
dashed ellipses natively.

Maintainability. wgpu ships a breaking major roughly every three months (v25
in early 2025, v30 now). My probe hit three compile errors from an API that
was current less than a year ago (`InstanceDescriptor::default`,
`RequestAdapterOptions` gained a field, `PollType::Wait` became a struct
variant). That is exactly the churn an agent doing most of the work pays for
on every dependency bump.

### 3.6 Python 3.12 + pygame-ce or arcade

Versions: pygame-ce 2.5.8, pygame 2.6.1, arcade 3.3.3, pyglet 2.1.16.

Install. `pip` and `ensurepip` are both absent (`No module named ensurepip`),
so `python -m venv` creates an environment without pip. Not fatal:
`bootstrap.pypa.io/get-pip.py` is reachable (HTTP 200) and works with a plain
interpreter, or `uv` can be installed by curl. It is one more undocumented
system step than any other candidate, and pytest, mypy and everything else
follow the same route.

Headless. Easy: `SDL_VIDEODRIVER=dummy` plus `pygame.image.save`. Arcade needs
an OpenGL context, which is harder without a display.

Runtime. The simulation and especially planner scrubbing in pure Python are
50x to 100x slower than V8 or WASM. NumPy vectorisation fits the tier-two
integrator but not the per-object substep ladder cleanly, and NumPy's SIMD
reductions can change summation order across CPUs, which is a determinism
hazard rule 5 forbids.

GitHub Pages. pygbag packages CPython to WASM; the runtime download is tens of
MB and startup is seconds. It works, but it is the heaviest web story here.

Determinism. CPython floats are IEEE doubles; `math.sin` is the platform
libm, so same-machine determinism holds and cross-platform does not.

### 3.7 Bun-only toolchain (bun install, bun build, bun test)

Versions: bun 1.3.10 (installed). Bun's bundler takes an HTML entry and emits
a static site; `bun test` is Jest-compatible; `bun.lock` is a text lockfile.

Measured: `bun install` 1.5 s, node_modules 210 MB (hoisted layout), `bun.lock`
31 kB; `bun test` on a trivial file 0.05 s and 39 MB. Impressively light.

The disqualifier is engine mismatch. Bun runs JavaScriptCore; the shipped game
runs V8 (and SpiderMonkey). My probe showed JavaScriptCore's `Math.sin`,
`cos`, `tan`, `atan2`, `exp`, `log`, `hypot`, `cbrt` and more differ from
both Node's and Chrome's. Golden hashes recorded under `bun test` would not
be the hashes the browser produces unless the sim owns its math (section 6),
and even then the test engine would not be the shipping engine. Playwright
also officially targets Node. Bun remains useful as a free third engine for
the parity test, not as the toolchain.

### 3.8 Zig 0.16 + raylib 6.0

Versions: zig 0.16.0 is present at `~/.local/bin/zig` (the environment brief
listed it as missing); raylib-zig targets raylib 6.0 and Zig 0.16.

Headless needs a display (raylib opens a window; the DRM platform needs a
device). Web needs Emscripten, which is not installed. Zig is pre-1.0 and
breaks every release; raylib-zig follows with a lag. Test tooling is `zig
test`. Determinism is fine (Zig's `std.math` is self-contained). Not a
serious contender for an agent-maintained project in 2026.

### 5.2 Package manager: pnpm

- **Lockfile.** `pnpm-lock.yaml` (v9 format) is 40 kB and 1 236 lines for the
  whole toolchain, diff-friendly, and records integrity hashes per package
  once. Bun's `bun.lock` (31 kB) is also text, but Bun as package manager
  invites `bun run` and `bun test`, which execute on JavaScriptCore; keeping
  one runtime (V8, the shipping engine) matters here more than install
  speed. npm's `package-lock.json` is JSON, three to five times larger, and
  npm's flat `node_modules` permits phantom imports that pnpm's strict
  layout rejects, which is a real safeguard when an agent writes most imports.
- **Footprint.** 138 MB versus 210 MB for the identical dependency set under
  Bun, because pnpm hard-links from a content-addressable store.
- **Reproducibility.** `packageManager: "pnpm@11.25.0"` in `package.json`,
  `engines.node: ">=24 <25"`, `.nvmrc` = 24, CI uses `--frozen-lockfile`.

### 5.3 Directory layout

Single package, no monorepo; the sim boundary is enforced by tooling, not by
package splitting.

```
graviton/

  tsconfig.json          # whole project, lib: es2024 + dom
  tsconfig.sim.json      # src/sim only, lib: es2024, NO dom  -> proves sim is headless
  vite.config.ts  vitest.config.ts  playwright.config.ts
  index.html
  public/fonts/          # woff2 copied from @fontsource at build via a script
  src/

      math.ts            # own sin/cos/atan2/exp/log in plain arithmetic
      streams.ts         # named seeded PCG32 streams
      ephemeris.ts       # tier one: Keplerian, O(1) at time t
      integrator.ts      # tier two: symplectic fixed step + substep ladder
      signal.ts          # light-cone solvers, occlusion
      state.ts           # SoA typed arrays; serialize(); hash()
      commands.ts        # command log types and apply()
      level.ts           # level schema and loader (levels are data)
    levels/              # 01-intercept.ts ... 12-debris.ts, campaign.ts
    planner/             # ghost integration through sim's code path, per-node cache
    render/              # Canvas 2D against Ctx2D; palette, glyphs, spheres, overlays
    ui/                  # DOM panels: status bar, selection, timeline, exposure strip
    audio/               # Web Audio adapter + NullAudio
    app/                 # main.ts: loop, input, warp ladder, window.graviton handle
    headless/            # cli.ts: run/hash/render a level to tick N (Node + napi canvas)
  tests/
    sim/                 # golden replay, ghost invariant, warp invariance, round-trip, substep
    golden/              # <level>.log.json + <level>.hash per shipped level
    render/              # PNG snapshot tests through @napi-rs/canvas
    e2e/                 # Playwright: smoke, screenshots, engine parity
  scripts/               # new-work-item.ts, issues.ts, copy-fonts.ts (run with plain node)
  docs/                  # existing knowledge base
  .github/workflows/ci.yml   # lint, typecheck (both tsconfigs), unit, e2e, build, Pages deploy
```

How an agent renders frame N of level X:

```
pnpm sim --level 07-staleness --until 4200 --hash            # headless run, prints state hash
pnpm render --level 07-staleness --tick 4200 --out shot.png  # Node + Skia, ~0.1 s, no display
pnpm e2e:shot --level 07-staleness --tick 4200               # Playwright + Chromium, ~1 s
```

The web app reads `?level=&tick=&paused=1` on load and exposes
`window.graviton` (`load`, `step`, `apply`, `hash`, `render`) for
`page.evaluate`, so Playwright can drive the same commands the UI sends.
Screenshots use `deviceScaleFactor: 1`, a fixed viewport and `--disable-gpu`
so baselines are stable on one machine.

### 5.4 Determinism guard-rails

1. **Sim owns its transcendental math.** `src/sim/math.ts` implements `sin`,
   `cos`, `atan2`, `sqrt` (delegates to `Math.sqrt`, which is correctly
   rounded everywhere), and `exp`/`log` if hyperbolic orbits need them, as
   ports of the musl/fdlibm algorithms using only `+ - * /`, `Math.sqrt`,
   `Math.floor` and bit tricks. Tests assert within 1 ULP of `Math.*` and
   against fixed vectors. This single file is what makes the golden hashes
   identical in Node, Chromium and Firefox; my probes show that without it
   they will not be.
2. **oxlint overrides for `src/sim/**`** (all verified to fire):
   - `no-restricted-properties`: `Math.random`, `Math.sin`, `cos`, `tan`,
     `asin`, `acos`, `atan`, `atan2`, `exp`, `expm1`, `log`, `log1p`, `log2`,
     `log10`, `pow`, `hypot`, `cbrt`, `sinh`, `cosh`, `tanh`, `asinh`,
     `acosh`, `atanh`, `Date.now`, `performance.now`. Allowed: `sqrt`, `abs`,
     `floor`, `ceil`, `trunc`, `round`, `min`, `max`, `sign`, `fround`,
     `imul`, `clz32`.
   - `no-restricted-globals`: `Date`, `performance`, `setTimeout`,
     `setInterval`, `requestAnimationFrame`, `crypto`, `fetch`, `window`,
     `document`, `navigator`, `Intl`, `Set`, `Map`, `WeakMap`, `WeakSet`
     (dense arrays only, contract rule 5).
   - `no-restricted-imports`: patterns for `../render`, `../ui`, `../app`,
     `../audio`, `../planner`, and any npm package.
   - oxlint has no `no-restricted-syntax`, so the `**` operator (which is
     `Math.pow`) is caught by `scripts/check-sim-purity.ts`, a 30-line scan
     that also rejects `for...of` over anything but arrays in `src/sim`.
3. **Two tsconfigs.** `tsconfig.sim.json` omits the `dom` lib; CI typechecks
   it separately. Any DOM reference in the sim is a compile error.
4. **State as typed arrays.** Structure-of-arrays `Float64Array`/`Int32Array`
   per object class, so `hash()` is a byte walk and `serialize()` is base64
   of buffers plus a JSON header. No object-key ordering questions.
5. **Contract tests as spec'd**: golden replay per level, ghost invariant,
   warp invariance across the ladder, serialization round-trip, substep
   boundary determinism.
6. **Engine parity test in CI.** The same level and log is hashed in Vitest
   (Node V8), in Playwright Chromium and Firefox, and in `bun run` as a free
   JavaScriptCore check. Any drift means a `Math.*` or ordering leak got
   past the lint. This test is what turns the "same binary, same platform"
   contract into cross-platform identity at no runtime cost.
7. **Render never writes** is enforced by handing the renderer a
   `Readonly` view type over sim state and by the `no-restricted-imports`
   direction (sim imports nothing; everything imports sim).

## 6. Risks and mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Vitest 5.0.0 was published today and has fresh-major bugs | Medium | Pin 5.0.0; fallback is vitest 4.1.11, which also supports Vite 8 |
| TypeScript 7.0.2 has no stable programmatic API until 7.1; some plugins refuse it | Low for this stack | Nothing chosen needs the API. If one does, add `@typescript/typescript6` 6.0.2 (`tsc6`) for that tool only |
| Node upgrade changes `Math.*` again and shifts golden hashes | Certain over time | Guard-rail 1 removes `Math.*` from the sim; parity test catches leaks |
| Skia text anti-aliasing in Node differs slightly from Chrome | Certain | Keep two baseline sets (node, chromium); compare with a small per-pixel tolerance; use Node PNGs for layout checks and Chromium for final fidelity |
| Planner scrubbing too slow in JavaScript on large levels | Low | Per-node ghost cache as the spec demands; SoA typed arrays; if still short, port `src/sim` to Rust/WASM behind the same command/state API (runner-up path, verified deterministic) |
| oxlint rule gaps (`no-restricted-syntax`) | Certain | Purity script in CI; ban `Set`/`Map` globals instead of banning `for...of` |
| Playwright browser download on a fresh machine (~150 MB) | Certain on CI | CI caches `~/.cache/ms-playwright`; local cache already matches 1.62.1 |
| GitHub Pages base path breaks asset URLs | Low | `base: '/graviton/'` in Vite; e2e runs against `vite preview` with the same base |
| Font licensing or missing tabular numerals | Low | JetBrains Mono and Barlow Condensed are OFL; both have `tnum` |
| WebKit not testable locally (Playwright WebKit failed to launch, missing system libs) | Certain here | Not required; Chromium and Firefox cover V8 and SpiderMonkey. WebKit runs in CI if ever needed |
